## 2. Models `.map` 崩溃 — 根因 / 修复 / 验证

### 2.1 现象

- UI ErrorBoundary：`Something went wrong` / `a.map is not a function`（生产 bundle 中亦可表现为 `V.map is not a function`）。
- 栈落在 Models Token Usage History 渲染（`token-usage-entry` / `pagedUsageHistory.map`）。

### 2.2 根因

1. **直接原因：** usage 历史 payload **非数组**（例如 `{ entries: [...] }`、`{ data: [...] }`、空对象 envelope、或偶发非列表成功体），UI 对结果直接 `.map`。
2. **触发背景：** P4a 将 Models 切换为 `hostApi.usage.recentTokenHistory()` → `host:invoke` 返回体形状与历史 `hostApiFetch` 直接 JSON 数组路径不完全一致时，缺少统一 coerce。
3. **非根因（已排除方向）：** #1094 chat runtime 管道；M4 poll；secrets。

### 2.3 修复（`049855d6` + 纵深）

| 层 | 行为 |
|----|------|
| `normalizeUsageHistoryEntries` | array 原样；对象上 `entries\|items\|history\|records\|data\|result` 若为数组则取出；否则 `[]` |
| `hostApi.usage.recentTokenHistory` | **出口**始终 normalize |
| Models `index.tsx` | fetch 后、visible/stable、`pagedUsageHistory` 再 normalize |
| `usage-history.ts` | filter / group 入口 normalize |

### 2.4 验证证据（归档时）

| 检查 | 结果 |
|------|------|
| unit `usage-history-entries` + `models-usage-history` + `host-api-facade` | **21/21 PASS**（最终审核会话） |
| E2E Models host success / UNSUPPORTED→HTTP | 规格与稳定化 commits 在库：`8227d6b5` / `5ee3c571` |
| 最终只读审核 | P4a **CLOSE/GO**；无 Critical/High/Medium 阻断 |

### 2.5 与 transport 修复的关系（`3d4b8f75`）

- **问题：** 早期用 `message.includes('channel'|'bridge')` 启发式决定 fallback，会把业务 `INTERNAL`（文案含 “Channel is required…”）误判为传输失败并吞掉。
- **修复：** 仅当显式 code ∈ `{ UNSUPPORTED, BRIDGE_UNAVAILABLE, CHANNEL_UNAVAILABLE }` 才 fallback；业务错误 rethrow。
- **单测锚点：** `does not fallback when business error message contains "channel"`。
