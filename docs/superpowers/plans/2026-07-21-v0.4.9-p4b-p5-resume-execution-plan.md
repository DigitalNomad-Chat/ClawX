## 2. P4b — 按风险排序的 renderer 迁移

### 2.1 设计原则

1. **Registry-first：** 只迁移 Main **已** `registerCoreServices` 的 module/action；缺 action 则本批先 **扩 registry + thin wrapper 等价**（属 P3 残余补齐），再迁 renderer。
2. **先读后写、先非 Chat 后 Chat。**
3. **一批一域**；禁止「大爆炸」改 stores + chat 同 commit。
4. **页面禁止** 新增 `window.electron.ipcRenderer.invoke`；统一 `hostApi` / `api-client` / 既有 `kernel-client` 边界。
5. **ClawHub / skills status / gateway 控制面** 多数仍走 HTTP：可保留 `hostApiFetch`，或仅迁 **已有** host action。

### 2.2 明确排除项（P4b 全程）

| 排除 | 原因 |
|------|------|
| **v0.4.10** / OpenClaw 大版本 / OAuth 产品 | 计划硬禁 |
| **skills marketplace 解耦** / ClawHub 产品行为变更 | 硬禁；仅允许机械边界封装 |
| **删除** `hostapi:fetch` / `host-api-proxy` / 大面积 legacy handler | **P5** 且要证据 |
| **#1094 语义改动**（dual-emit、`phase=end`、poll gate、per-run evidence） | 仅允许 path alias 级机械改 |
| **Chat 发送 / history-poll / runtime-pipeline 内核**（B5 前） | R3；最后且单独授权 |
| **`chat:sendWithMedia` 超时或语义** | 180s 锁；P5 前不碰 |
| **member / auth / office-tools / desensitize / hermes** 业务重写 | 二开保留；非本阶段目标 |
| **providers 密钥落盘算法变更** | 只换传输边界，不改密钥模型 |
| **整包 cherry-pick `581981f2`** | 选择性移植 |
| 未在 registry 的 **agents 聚合 HTTP** 强行改 host 名 | 先补 P3 或保持 `hostApiFetch` |
| 生产启用 `clawdock:e2e-force-gateway-running` | 仅 E2E（R1） |

### 3.2 单通道删除门禁（缺一不可）

| # | 门禁 |
|---|------|
| 1 | `rg "channel-name" src electron tests` — renderer/preload **无**业务调用，仅剩 Main 注册与测试夹具说明 |
| 2 | 对应 `hostApi` action 有 unit +（若 UI）E2E 覆盖 |
| 3 | harness rule/task 更新（`prune-host-api-covered-legacy-ipc` 类）且 `harness validate` PASS |
| 4 | lead 确认 ClawDock 二开（member/office-tools/desensitize/hermes）无依赖 |
| 5 | 变更集 **不含** 下列默认保留项（除非另批书面批准） |

**默认永不在本阶段删除：**

- `hostapi:fetch` / `hostapi:token`
- `gateway:rpc` / `gateway:httpProxy`
- `chat:runtime-event` 与 dual-emit 相关
- `chat:sendWithMedia`（除非 registry 等价 **且** 180s 锁测）
- auth/member、office-tools、desensitize 专用通道

### 3.3 P5 执行序

```text
0. lead 授权 + 冻结「候选删除清单」
1. harness：收紧 prune 政策（先测试）
2. 按通道：rg 证据表 → 删 handler → unit/E2E/harness
```
