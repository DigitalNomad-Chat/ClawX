# 频道配置字段补齐执行计划

> 目标：将 OpenClawSwitch 参考项目中"访问策略""连接模式""高级配置"三个模块的缺失配置字段完整移植到 ClawX 项目
> 制定日期：2026-05-18
> 关联文档：《频道配置移植差距分析报告.md》

---

## 一、项目概况

### 1.1 现状
当前 ClawX 的频道编辑界面已从 OpenClawSwitch 移植了"访问策略""连接模式""高级配置"三大模块的 UI 框架和大部分字段，但仍有约 30% 的关键字段未移植，尤其以飞书(Feishu)频道最为严重。

### 1.2 目标
补齐所有 8 个已启用频道的缺失配置字段，确保前端 UI 可配置、后端可存储、运行时生效。

### 1.3 范围
- **涵盖频道**：Feishu、Telegram、Discord、Slack、WeCom、WhatsApp、DingTalk、QQBot
- **涉及系统**：前端 UI(React)、前端类型定义、i18n 翻译、后端配置存储、后端运行时读取
- **不涉及**：新增频道类型、修改现有字段交互逻辑、重构配置面板架构

---

## 二、执行策略

### 2.1 总体策略
采用**"先核心后边缘、先飞书后其他、先字段后交互"**的分层递进策略：

1. **基础设施层**：扩展类型系统与翻译文件，为所有字段提供类型支持和多语言标签
2. **核心频道层**：优先补齐飞书(Feishu)的 10 个缺失字段（影响面最大、用户最关注）
3. **通用能力层**：补齐跨频道通用字段（network、proxy、groups 等）
4. **边缘功能层**：补齐各频道特有的进阶字段（连接管理、动态 Agent 等）
5. **验收验证层**：端到端测试，确保配置可保存、可读取、运行时生效

### 2.2 分支策略
基于当前 `feature/independent-kernel` 分支创建子分支：

```bash
git checkout feature/independent-kernel
git pull
git checkout -b feature/channel-config-completion
```

每完成一个阶段独立 commit，采用 Conventional Commits 规范。

## 五、风险与对策

| 风险项 | 影响 | 对策 |
|--------|------|------|
| **后端有字段白名单** | 新增字段保存后被过滤 | Phase 1.3 先排查后端白名单，若存在则同步扩展 |

| **DingTalk connection 模块新增** | 可能影响现有布局 | 按现有 Tab 导航模式新增 connection 面板，保持 UI 一致 |
