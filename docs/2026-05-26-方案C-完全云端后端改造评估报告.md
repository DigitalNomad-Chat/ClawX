## 二、影响范围评估

### 2.1 前端层：零改动

前端通过 IPC 通道与主进程通信，IPC 接口保持不变。以下文件**不需要修改**：

| 文件 | 说明 |
|------|------|
| `src/stores/auth.ts` | 通过 `invokeIpc('auth:*')` 调用，接口不变 |
| `src/pages/ActivationPage.tsx` | 调用 `auth.activateLicense()`，不变 |
| `src/components/auth/UserBadge.tsx` | 读取 auth store 状态，不变 |
| `src/components/auth/LoginModal.tsx` | 调用 `auth.login()/register()`，不变 |
| `src/hooks/useFeatureGuard.ts` | 调用 `auth.checkFeature()`，不变 |
| `src/types/auth.ts` | UserInfo/UsageInfo/Tier 类型不变 |
| `src/i18n/locales/*/auth.json` | 不变 |

**关键设计决策**：所有改造发生在 Electron 主进程 IPC handler 层和云端服务端。前端通过 IPC 通道与主进程通信的架构天然隔离了后端变化。

### 2.2 Electron 主进程层：大幅重写

| 文件 | 当前职责 | 改造影响 | 工作量 |
|------|---------|---------|--------|
| `member-manager.ts` | 本地 SQLite 注册/登录 | **完全重写**：改为 HTTP 代理到云端 API | 高 |
| `token-manager.ts` | 本地 JWT 签发 | **完全重写**：接收云端 token，本地缓存 | 高 |
| `usage-counter.ts` | 本地 SQLite 计数 | **大幅修改**：在线时上报云端，离线时本地缓存 | 中 |
| `index.ts` | 模块初始化编排 | **大幅修改**：移除本地 DB 初始化，增加 API 基础 URL 配置 | 中 |
| `database.ts` | 本地 SQLite 全套 | **大幅精简**：仅保留离线缓存，移除 users/subscriptions 表 | 中 |
| `local-auth.ts` | bcrypt/JWT 工具 | **精简**：移除 signJwt/hashPassword，保留 verifyJwt 用于本地验证缓存 token | 低 |
| `subscription.ts` | 等级配置 | **修改**：可从云端同步 tier 配置，本地缓存 | 低 |
| `verification.ts` | 在线 License 验证 | **保持**：已有 HTTP 调用，可能调整 URL | 极低 |
| `activation.ts` | License → 本地激活 | **修改**：改为通过云端 auth API 激活 | 低 |
| `migrate.ts` | 旧数据迁移 | **可移除**：迁移完成后不再需要 | 极低 |
| `auth-handlers.ts` | IPC 处理器 | **修改**：handler 内部改为调 HTTP API，接口签名不变 | 中 |
| `event-bus.ts` | 内部事件 | **保持** | 无 |
| `network-detector.ts` | 网络状态检测 | **保持**，且更重要（在线/离线切换） | 无 |

### 2.3 云端服务层：大幅扩展

当前 `server/` 已有 License 验证服务。需要扩展为完整后端：

| 新增模块 | 端点数 | 说明 |
|---------|--------|------|
| 认证模块 (auth) | 4 | register, login, logout, me |
| 用量模块 (usage) | 3 | check, record, stats |
| 管理模块-用户 (admin-users) | 3 | list, get, update |
| 管理模块-等级 (admin-tiers) | 2 | list, update |
| 管理模块-统计 (admin-stats) | 1 | dashboard 数据 |
| 管理界面 (admin-ui) | 1 | 静态 SPA 页面 |
| **已有** License 模块 | 3+3 | activate, verify + admin CRUD |

## 三、API 契约设计

### 3.1 IPC 通道 → 云端 API 映射

| IPC 通道 | 当前处理方式 | 云端 API | 方法 |
|----------|------------|----------|------|
| `auth:login` | 本地 SQLite 查询 | `POST /v1/auth/login` | `{ username, password, deviceId }` |
| `auth:register` | 本地 SQLite 插入 | `POST /v1/auth/register` | `{ username, email, password, deviceId }` |
| `auth:logout` | 本地清空状态 | `POST /v1/auth/logout` | Bearer token |
| `auth:getUser` | 本地内存读取 | `GET /v1/auth/me` | Bearer token |
| `auth:checkFeature` | 本地 SQLite 计数 | `GET /v1/usage/check?feature=X` | Bearer token |
| `auth:recordUsage` | 本地 SQLite +1 | `POST /v1/usage/record` | Bearer token + `{ feature }` |
| `auth:getUsageStats` | 本地内存读取 | `GET /v1/usage/stats` | Bearer token |
| `auth:activate` | 云端验证 + 本地写入 | `POST /v1/license/activate` | Bearer token + `{ licenseKey }` |

### 3.2 云端 API 详细设计

#### 认证端点

**POST /v1/auth/register**
```

成功: { success: true, user: UserInfo, token: string }
失败: { success: false, reason: string }
```

**POST /v1/auth/login**
```
请求: { username, password, deviceId }
成功: { success: true, user: UserInfo, token: string }
失败: { success: false, reason: string }
```

**POST /v1/auth/logout**
```
请求: (Bearer token in header)
成功: { success: true }
```

**GET /v1/auth/me**
```
请求: (Bearer token in header)
成功: UserInfo
失败: 401 Unauthorized
```

#### 用量端点

**GET /v1/usage/check?feature=collaboration**
```
请求: (Bearer token)
成功: UsageInfo { feature, used, limit, remaining, tier, allowed }
```

**POST /v1/usage/record**
```
请求: (Bearer token) + { feature, triggerAction? }
成功: { success: true }
```

## 四、D1 数据库设计

### 4.1 完整 Schema

```sql
-- 用户表
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  username TEXT UNIQUE NOT NULL,
  email TEXT UNIQUE NOT NULL,

  tier TEXT NOT NULL DEFAULT 'free', -- free | pro | enterprise

  created_at INTEGER NOT NULL,
  expires_at INTEGER NOT NULL

CREATE INDEX idx_sessions_user ON sessions(user_id);
CREATE INDEX idx_sessions_expires ON sessions(expires_at);

-- License Key 表（已有，扩展）
CREATE TABLE licenses (
  id TEXT PRIMARY KEY,

  tier TEXT NOT NULL DEFAULT 'pro',

  activated_count INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,

);

-- 设备激活表（已有，关联 user_id）

  id TEXT PRIMARY KEY,
```

| 表 | 本地 SQLite | D1 云端 | 说明 |

## 五、客户端改造方案

### 5.1 核心改造思路

**不改前端，只改 IPC Handler 层**。前端通过 `invokeIpc('auth:*')` 调用 IPC，IPC handler 内部从"调用本地 MemberModule"改为"调用云端 HTTP API"。

```
前端 (不变)           IPC Handler (改造)           云端 API
─────────────     ─────────────────────     ──────────────
auth:login    →   handler 改为 fetch()   →   POST /v1/auth/login
                  返回 { success, user }
                  缓存 token 到 electron-store
```

### 5.2 新增配置项

在 `electron/utils/store.ts` 的 `AppSettings` 中新增：

```typescript
// Membership Cloud API
cloudApiBaseUrl: string;      // 默认: 'https://api.clawx.app/v1'
cloudApiEnabled: boolean;     // 默认: true（云端模式）
```

### 5.3 改造后的 auth-handlers.ts 示例

```typescript
// 改造前（本地 SQLite）
ipcMain.handle('auth:login', async (_, { username, password }) => {
  const result = await memberModule.manager.login({ username, password, deviceId });
  return result;
});

// 改造后（HTTP 代理到云端）
ipcMain.handle('auth:login', async (_, { username, password }) => {
  const response = await fetch(`${apiBaseUrl}/auth/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ username, password, deviceId }),
  });
  const result = await response.json();
  if (result.success) {
    // 缓存 token 到 electron-store
    await setSetting('cloudAuthToken', result.token);
    await setSetting('userInfo', result.user);
  }
  return result;
});
```

### 5.4 离线降级策略

```
在线状态:
  auth:login    → 云端 API → 返回用户信息 + token
  auth:getUser  → 云端 API → 返回最新用户信息
  auth:checkFeature → 云端 API → 返回配额信息

离线状态:
  auth:login    → 提示"无法连接服务器"
  auth:getUser  → 读取 electron-store 缓存
  auth:checkFeature → 读取本地缓存（配额可能不准确）
  auth:recordUsage → 记录到本地队列，上线后同步
```

## 七、改造风险评估

### 7.1 技术风险

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| Cloudflare Workers CPU 限制（密码哈希可能超时） | 中 | 使用 Web Crypto PBKDF2（硬件加速），控制在 10ms 内 |
| D1 数据库写入延迟 | 低 | D1 在边缘节点，延迟 <50ms |
| 用户首次升级数据丢失 | 中 | 提供迁移脚本：本地 SQLite → 云端 API 同步 |
| 离线场景功能受限 | 中 | 保留本地缓存，关键操作（登录）需在线 |
| API 安全性 | 中 | JWT + CORS + Rate Limiting + Input Validation |
| D1 免费额度限制（5GB 存储，5M 读/天，100K 写/天） | 低 | 初期用户量远低于限制，可监控 |

### 7.2 用户体验风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 必须联网才能注册/登录 | 高 | 保留离线模式提示，缓存登录状态 |
| 网络延迟影响操作响应 | 中 | 本地缓存 + 异步操作，300ms 内可接受 |
| 旧版本不兼容 | 中 | 版本检测，提示升级 |

## 十、方案对比总结

| 维度 | 当前（本地优先） | 方案 C（完全云端） |
|------|----------------|------------------|
| **注册/登录** | 本地 SQLite + bcrypt | 云端 D1 + PBKDF2 |
| **Token 管理** | 本地 JWT 自签发 | 云端签发，本地缓存 |
| **用量计数** | 本地 SQLite | 云端 D1 + 本地离线队列 |
| **会员等级** | 硬编码在 subscription.ts | 数据库动态配置，管理员可调 |
| **License 验证** | 云端（已实现） | 云端（不变） |
| **离线支持** | 完全可用 | 降级模式（缓存读取） |
| **管理能力** | 无（仅 API） | Web 后台（用户/等级/License/统计） |
| **数据归属** | 用户本地 | 云端 + 本地缓存 |
| **改造成本** | - | 7天 |
| **维护成本** | 低（纯本地） | 中（需维护云端服务） |
| **扩展性** | 差（本地限制） | 好（云端可水平扩展） |

## 十一、建议执行顺序

1. **先完成阶段 A（云端 API）**— 独立于客户端，可独立测试
2. **再完成阶段 B（客户端改造）**— 依赖阶段 A 的 API
3. **并行完成阶段 C（管理后台）**— 依赖阶段 A 但不依赖 B
4. **阶段 D（迁移工具）**— A+B 完成后执行
5. **阶段 E（测试）**— 全部完成后统一测试

## 十二、待决策事项

1. **云端 API 域名**：`https://api.clawx.app/v1` 是否确认？需要配置 Cloudflare 域名。
