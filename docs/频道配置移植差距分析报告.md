# 频道配置移植差距对比分析报告

> 对比范围：ClawDock（当前项目）vs OpenClawSwitch（参考项目）
> 对比维度：访问策略 / 连接模式 / 高级配置 三大模块的字段完整度
> 分析日期：2026-05-18

---

## 一、总体概述

经逐字段比对，当前 ClawDock 项目的频道编辑界面在从 OpenClawSwitch 移植"访问策略""连接模式""高级配置"三个模块时，**飞书(Feishu)频道的缺失最为严重**，其余频道（Telegram、Discord、Slack、DingTalk、WeCom、QQ、WhatsApp 等）也存在不同程度的字段遗漏。

**核心结论**：
- 已移植字段约占参考项目的 **55%~70%**
- 飞书频道缺失 **10 个配置项**，为所有频道中最多的
- 部分字段在翻译文件(i18n)中已有定义，但在类型定义(CHANNEL_META)中未接入
- 部分字段属于 OpenClawSwitch 较新版本(2026.4.x+) 新增功能

## 三、缺失字段分类汇总

### 3.1 按功能分类

| 功能类别 | 涉及频道 | 缺失字段 |
|----------|----------|----------|
| **群组级精细配置** | Feishu, Telegram, Discord, Slack, WeCom, WhatsApp, DingTalk | `groups`, `guilds`, `channels` |
| **回复/路由模式** | Telegram, Discord, Slack, WhatsApp | `replyToMode`, `defaultTo` |
| **网络与代理** | Feishu, Telegram, Discord, Slack, WeCom, WhatsApp, DingTalk | `network`, `proxy` |
| **Webhook 安全** | Feishu | `encryptKey`, `verificationToken` |
| **连接管理(重连)** | DingTalk | `maxConnectionAttempts`, `initialReconnectDelay`, `maxReconnectDelay`, `reconnectJitter`, `maxReconnectCycles`, `useConnectionManager` |
| **动态 Agent** | Feishu | `dynamicAgentCreation` |
| **交互增强** | Feishu, WeCom | `typingIndicator`, `sendThinkingMessage` |
| **@提及绕过** | Feishu | `groupCommandMentionBypass` |
| **域名切换** | Feishu | `domain` (feishu/lark) |
| **模板卡片** | DingTalk | `cardTemplateId`, `cardTemplateKey` |
| **消息分块** | Slack | `textChunkLimit`, `chunkMode` |

### 3.2 按严重程度分级

| 级别 | 判定标准 | 涉及字段 |
|------|----------|----------|
| **🔴 高** | 影响核心功能、安全或用户体验 | `domain`(飞书), `groups`(多频道), `encryptKey`, `verificationToken`, `groupCommandMentionBypass`, `dynamicAgentCreation` |
| **🟡 中** | 影响进阶功能或运维能力 | `proxy`(多频道), `network`(多频道), `typingIndicator`, `replyToMode`, `webhookPort`(飞书) |
| **🟢 低** | 优化体验或边缘场景 | `cardTemplateId`, `cardTemplateKey`, `textChunkLimit`, `chunkMode`, `sendThinkingMessage`, `proactivePermissionHint` |
