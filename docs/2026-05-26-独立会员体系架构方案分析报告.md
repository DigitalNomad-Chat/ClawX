## 二、四种架构方案对比

### 2.1 方案总览

| 方案 | 核心思路 | 一句话 |
|------|---------|--------|
| A. 纯本地 | 仅激活时在线验证一次 | 最简单，最易破解 |
| B. 本地+定期校验 | 本地运行，定期静默校验令牌 | **推荐：安全性与成本的平衡** |
| C. 云端优先 | 自建完整后端，始终在线鉴权 | 最安全，成本最高 |
| D. 混合分层 | 基础功能本地，高级功能在线验证 | 体验好，架构最复杂 |

### 2.2 多维对比

| 维度 | A. 纯本地 | B. 本地+定期校验 | C. 云端优先 | D. 混合分层 |
|------|----------|----------------|------------|------------|
| **离线可用性** | 完全可用 | 激活后可用N天 | 不可用 | 基础功能可用 |
| **防破解难度** | 低 | 中 | 高 | 高 |
| **运营成本** | 极低 | 低 | 中高 | 中 |
| **用户体验** | 最流畅 | 几乎无感 | 依赖网络 | 分层体验 |
| **多设备支持** | 不支持 | 可选支持 | 原生支持 | 可选支持 |
| **开发工时** | 12-17天 | 15-20天 | 25-35天 | 20-28天 |
| **基础架构需求** | 无服务器 | 轻量API服务 | 完整后端+数据库 | 轻量后端+本地DB |

## 三、各方案详细分析

### 方案A：纯本地（仅激活时在线）

```
激活时在线验证一次 → 签名数据本地缓存 → 离线运行至过期
```

**优势：**
- 零服务器运维，成本最低
- 完全离线可用，不依赖网络
- 实现最简单，工时最短
- 用户体验最流畅（无网络等待）

**劣势：**
- 防破解最弱：本地数据可被逆向分析篡改
- 会员到期靠本地时间，改系统时间可绕过
- 无法追踪用户行为/使用数据
- 无法支持多设备、云同步
- "无限试用"风险高

**适合场景：** 用户群体付费意愿高、信任度高的社区产品

---

### 方案B：本地优先 + 定期在线校验（推荐）

```
本地运行 → 每隔 N 小时静默向服务端校验一次 → 刷新会员令牌
校验失败 → 给予宽限期（如72h）→ 过期则降级为 Free
```

**优势：**
- 离线容忍度高（72h宽限期，出差/断网不受影响）
- 防破解显著增强：令牌定期刷新，篡改会在下次校验时被修正
- 可收集匿名使用数据，辅助产品决策
- 可在服务端随时吊销 License（如退款、违规）
- 仍只需极轻量API（2-3个接口）

**劣势：**
- 需要 7×24 在线的验证服务（虽极轻量）
- 用户长时间离网（>72h）会降级
- 服务端宕机会影响用户体验（但有宽限期兜底）
- 需处理校验失败的边界情况

**适合场景：** 大多数桌面软件的标准做法（JetBrains、Sublime Text 等均采用）

**所需在线接口（仅2个）：**
```
POST /api/v1/license/verify   -- 验证并刷新令牌
POST /api/v1/license/activate -- 首次激活
```

**基础设施：** Cloudflare Workers 免费额度即可承载

---

### 方案C：云端优先（自建完整后端）

```
所有会员操作走服务端 → 服务端鉴权 → 客户端仅为UI层
类似当前 guada_ai 架构，但换成自己的后端
```

**优势：**
- 防破解最强：核心鉴权逻辑在服务端，客户端无法绕过
- 完整用户管理：多设备、云同步、行为分析
- 灵活的运营能力：AB测试、动态定价、优惠活动
- 数据驱动：用户画像、留存分析、收入报表
- 未来扩展性强：团队协作、数据同步等高级功能

**劣势：**
- 开发工时最长（需自建完整后端）
- 必须在线才能使用（断网=无法使用）
- 运营成本：服务器 + 数据库 + CDN + 运维
- 运维复杂度：需要监控、备份、容灾
- 相当于重新造一个 guada_ai 后端

**适合场景：** SaaS 产品、团队协作工具、大规模商业化运营

---

### 方案D：混合分层

```
基础功能（AI对话、文档查看）→ 本地免登录即可使用
高级功能（协作大厅、应用广场）→ 在线验证会员后解锁
使用高级功能时 → 静默校验（有短时缓存，如4h）
```

**优势：**
- 渐进式体验：用户先用后买，降低付费门槛
- 核心高级功能防破解强（服务端鉴权）
- 基础体验不受网络影响
- "试用转化"路径更自然：先免费体验 → 遇到高级功能 → 引导升级
- 可精确控制每个功能的验证频率

**劣势：**
- 架构最复杂：需要同时维护本地和在线两套鉴权路径
- 每个新功能需要决定是"基础"还是"高级"
- 高级功能在离线时不可用（可能引发用户不满）
- 开发和维护成本介于方案B和C之间

**适合场景：** Freemium 产品，有明确的免费/付费功能边界

### 5.2 数据层：嵌入 SQLite

**选型**：`better-sqlite3`（同步API，适合 Electron 主进程）
**备选**：`sql.js`（纯WASM，无 native 依赖，包体稍大）

**数据表设计**：

```sql
-- 用户表
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  username TEXT UNIQUE NOT NULL,
  email TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  tier TEXT DEFAULT 'free',           -- free/pro/enterprise
  avatar_url TEXT,
  created_at INTEGER,
  updated_at INTEGER
);

-- 会员订阅表
CREATE TABLE subscriptions (
  id TEXT PRIMARY KEY,
  user_id TEXT REFERENCES users(id),
  tier TEXT NOT NULL,
  status TEXT DEFAULT 'active',       -- active/expired/cancelled
  started_at INTEGER,
  expires_at INTEGER,
  activated_by TEXT,                  -- license_key / activation_code
  created_at INTEGER
);

-- 功能使用记录（月度配额）
CREATE TABLE feature_usage (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id TEXT REFERENCES users(id),
  feature TEXT NOT NULL,              -- collaboration/marketplace/...
  year_month TEXT NOT NULL,           -- '2026-05'
  used_count INTEGER DEFAULT 0,
  UNIQUE(user_id, feature, year_month)
);

-- 激活记录
CREATE TABLE activations (
  id TEXT PRIMARY KEY,
  user_id TEXT REFERENCES users(id),
  license_key TEXT UNIQUE,
  device_fingerprint TEXT,
  tier TEXT,
  activated_at INTEGER,
  expires_at INTEGER,
  last_verified_at INTEGER,           -- 上次在线校验时间
  verification_data TEXT              -- 签名数据，防篡改
);
```

### 5.3 认证层：本地注册/登录

| 操作 | 实现 |
|------|------|
| 注册 | `bcrypt.hash(password, 12)` → 存入 SQLite users 表 |
| 登录 | `bcrypt.compare(password, hash)` → 签发本地 JWT |
| JWT签发 | 本地 RSA/Ed25519 密钥对签名，payload 含 userId + tier |
| 会话管理 | JWT 存于 `electron-store`（加密），24h 过期自动续签 |
| 设备绑定 | 复用现有 `native/` 模块的硬件指纹 |

### 5.4 会员层

| 会员等级 | 月度配额 | 定价（建议） | 功能权限 |
|---------|---------|------------|---------|
| **Free** | 3次/功能/月 | 免费 | 基础 AI 对话、文档查看 |
| **Pro** | 无限 | ¥49/月 或 ¥399/年 | 协作大厅、应用广场、文档编辑/OCR/脱敏 |
| **Enterprise** | 无限 | ¥199/月 | 全部功能 + 数据分析/报告 + 批量导出 + 本地API |

### 5.5 令牌校验流程

```
1. 用户激活 → License Key 在线验证 → 签发令牌（含过期时间+设备指纹+签名）
2. 令牌本地缓存（AES-256-GCM 加密存储）
3. 每 N 小时（建议 8h）静默校验：
   - 在线：向验证服务发送当前令牌 → 服务端验证并返回新令牌
   - 离线：检查本地令牌签名 + 过期时间 + 宽限期
4. 宽限期策略：
   - 最后一次成功校验后 72h 内 → 正常使用
   - 超过 72h → 降级为 Free（保留数据，仅限制高级功能）
   - 恢复网络后 → 自动重新校验并恢复会员状态
```

### 5.6 支付/激活流程

```
用户购买流程：
1. 用户访问支付页面（托管在第三方或自建H5）
2. 支付成功后获得 License Key（格式：CLWX-XXXX-XXXX-XXXX）
3. 在 ClawX 中输入 License Key
4. ClawX 在线验证 → 激活本地会员状态
5. 激活数据签名加密存储，离线可用直到过期

在线验证服务（极轻量，仅2个接口）：
POST /api/v1/license/verify   -- 验证并刷新令牌
POST /api/v1/license/activate -- 首次激活
```

## 七、风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 本地会员数据被篡改（破解） | 高 | AES-256-GCM 加密 + RSA 签名验证 + 定期在线校验修正 |
| better-sqlite3 native编译问题 | 中 | 备选 `sql.js`（纯WASM，无native依赖） |
| 支付信任链断裂 | 中 | 激活码必须在线验证，签名后离线可用 |
| 用户长时间离网导致降级 | 低 | 72h 宽限期，恢复网络自动恢复 |
| 用户换设备会员丢失 | 低 | 首期不处理，后续加云同步增值功能 |
| 验证服务宕机 | 低 | 宽限期兜底 + 客户端指数退避重试 |
| 数据迁移兼容性 | 低 | 编写 electron-store → SQLite 迁移脚本 |

## 八、待确认事项

1. **数据库选型**：`better-sqlite3`（性能优，需native编译）vs `sql.js`（纯JS，包体稍大）
2. **校验频率**：建议每 8 小时，可根据需要调整
3. **宽限期**：建议 72 小时，可根据用户场景调整
4. **支付渠道**：自建H5支付页 / 第三方（Lemonsqueezy/Paddle）/ 仅激活码
5. **是否需要多设备同步**：影响架构复杂度
6. **是否需要管理后台**：如果规模化运营需要
7. **是否复用本地 License（native C++模块）**：当前已冻结，可以激活或废弃
8. **验证服务部署**：Cloudflare Workers / Vercel Serverless / 自建轻量服务器
