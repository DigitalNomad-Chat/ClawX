## 一、本次执行内容

### P0：对话报错排查（部分完成）

**问题：** 聊天界面发送消息 90 秒后触发安全超时：
```
No response received from the model. The provider may be unavailable...
```

**已做的代码层增强：**

1. **`electron/api/routes/gateway.ts` SSE 代理健壮性**
   - `/api/chat/send` 和 `/api/chat/send-with-media` 在转发 Hermes Gateway `/v1/responses` 响应前，现在会**检查上游 `Content-Type`**。
   - 若上游返回的不是 `text/event-stream`，代理不再假装 SSE，而是直接返回 **502 JSON 错误**（包含上游 body 前 200 字符），帮助快速定位格式不匹配问题。
   - 增加了日志：`[chat/send] Proxying SSE stream...` 和 `SSE stream ended...`

2. **`src/stores/chat.ts` `consumeChatSse` 调试日志**
   - 增加流开始/结束日志（含 `runId` 和 `sessionKey`）
   - 每次成功解析 SSE `data:` JSON 后，记录事件 keys、done 状态和 error 状态
   - 这些日志会出现在 Electron DevTools Console，可据此判断 Gateway 实际返回的 SSE 事件结构

**下一步（需用户配合）：**
- 启动应用，在 DevTools 中观察 `[consumeChatSse]` 日志
- 若看到 `Upstream returned non-SSE content-type`，说明 Gateway 未返回 SSE，需要检查 Hermes Gateway 配置或 Provider
- 若日志正常显示事件 keys，但内容为空或不包含 `content` 字段，说明 SSE 格式与解析器不匹配，需进一步调整 `consumeChatSse`
