## 一、对话报错排查（高优先级）

### 问题描述
用户在聊天界面发送消息时出现错误：
```
No response received from the model. The provider may be unavailable or the API key may have insufficient quota. Please check your provider settings.
```

### 根因分析
该错误来自 `src/stores/chat.ts:2267`，是一个安全超时机制：
- `SAFETY_TIMEOUT_MS = 90_000`（90秒）
- 如果发送消息后 90 秒内 `_lastChatEventAt` 未被更新（即未收到 SSE 事件），触发错误
- `_lastChatEventAt` 在 `handleChatEvent` / `consumeChatSse` 中更新

### 排查步骤
1. **检查 Hermes Gateway 是否正常运行**
   - 验证 `hermes gateway start --profile default` 是否能成功启动
   - 检查 Gateway 日志是否有错误

2. **检查 SSE 流格式**
   - `consumeChatSse` 使用通用解析器，假设 SSE `data:` 行包含 JSON
   - Hermes Gateway 的 `/v1/responses` 返回的 SSE 格式可能与解析器不匹配
   - 需要确认 Hermes 实际返回的 SSE 事件格式

3. **检查模型 Provider 配置**
   - 确认 default profile 的 `config.yaml` 中已配置 AI provider（API key、model 等）
   - 确认 `.env` 文件中有正确的 API key

4. **检查网络连通性**
   - Host API (:13210) → Gateway (:8642) 代理是否正常
   - 直接 curl 测试 Gateway `/v1/responses` 端点

### 已执行的代码层增强
- **SSE 代理健壮性**：`electron/api/routes/gateway.ts` 中 `/api/chat/send` 和 `/api/chat/send-with-media` 现在会检查上游 Gateway 响应的 `Content-Type`。若返回非 `text/event-stream`，代理不再假装 SSE，而是直接返回 502 JSON 错误（含上游 body 片段），帮助定位格式不匹配问题。
- **调试日志**：`consumeChatSse` 已增加 `console.log`，记录流开始/结束以及每个解析事件的 keys、done、error 状态，便于在 DevTools 中观察 Gateway 实际返回的 SSE 事件结构。

### 修复方案
- 如果 SSE 格式不匹配：更新 `consumeChatSse` 解析逻辑
- 如果 Gateway 未启动：修复启动逻辑或添加错误提示
- 如果 Provider 未配置：引导用户配置
