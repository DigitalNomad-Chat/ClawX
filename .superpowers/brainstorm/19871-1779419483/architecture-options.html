会员系统架构方案对比

三种集成方案，推荐方案 C（混合在线+离线验证）

A

纯在线验证

每次使用高级功能都调用 guada_ai 后端 API 验证会员状态

优点

  • 实时性强，状态同步快
  • 实现最简单

缺点

  • 必须联网，离线不可用
  • 频繁请求后端，延迟高
  • 后端压力大
B

纯离线 Token（guada_ai 原生模式）

ClawX 启动时从 guada_ai 获取 Feature Token，本地 RSA 验签，离线也能用

优点

  • 完全离线可用
  • 不依赖网络
  • 与 guada_ai 桌面端一致

缺点

  • 状态同步有延迟（24h续签）
  • 无法实时限制（过期后还能用）
  • 次数限制需本地计数，易被篡改
C

混合模式（推荐）

在线时：API 实时验证会员状态和次数限制
离线时：Feature Token 本地验证，允许有限使用

优点

  • 在线时实时精确控制次数
  • 离线时通过 Token 兜底
  • 兼顾体验与安全性
  • 与 guada_ai 现有架构兼容

缺点

  • 实现复杂度中等
  • 需要设计在线/离线切换逻辑
